Additional information: 

Scanned the complete source available from https://github.com/jqlang/jq/archive/96e8d893c10ed2f7656ccb8cfa39a9a291663a7e.zip using ScanCode.io, which was then used to generate an SPDX 2.3 SBOM from the scan results.

Imported the SBOM generated by ScanCode.io into a DejaCode product. Discovered that the dependencies identified by ScanCode included both packages identified in the pipfile, which were without version, as well as the pipfile.lock, which have the specific versions actually used by the project, and used DejaCode to remove the packages without version, which were duplicates. 

Used a private tool, nexb-toolkit, to run a "cpp_includes" that identified a build dependency, oniguruma@d2f1a14, at https://github.com/jqlang/jq/tree/96e8d893c10ed2f7656ccb8cfa39a9a291663a7e/modules and added that to the project inventory.

Used DejaCode to curate the project inventory to improve the License assignments. Generated CycloneDX 1.6 and SPDX 2.3 SBOMs using DejaCode. The jq_project_source SBOM filenames are: 

- nexb_dejacode_jq_project_source_96e8d893c10ed2f7656ccb8cfa39a9a291663a7e.spdx.json
- nexb_dejacode_jq-project-source_96e8d893c10ed2f7656ccb8cfa39a9a291663a7e.cdx.json
 
Examined the scan results more closely in ScanCode.io and noted that all of the resolved dependencies had been identified in the /docs/ folder and were only required to build the documentation, and are not part of the actual deployed jq application. Created a separate product in DejaCode that included only the package pkg:github/jqlang/jq@96e8d893c10ed2f7656ccb8cfa39a9a291663a7e and its build dependency oniguruma@d2f1a14 and generated (much simpler) SBOMs. The jq_as_deployed SBOM filenames are: 

- nexb_dejacode_jq_as_deployed_96e8d893c10ed2f7656ccb8cfa39a9a291663a7e.spdx.json
- nexb_dejacode_jq-as-deployed_96e8d893c10ed2f7656ccb8cfa39a9a291663a7e.cdx.json

The SBOMs are source SBOMs, but we believe that including the oniguruma@d2f1a14 package from https://github.com/jqlang/jq/tree/96e8d893c10ed2f7656ccb8cfa39a9a291663a7e/modules provides the functional equivalent of a build SBOM.

No security vulnerabilities were detected in any of the identified software objects.
